# Active and inactive compression storage

`UF_COMPRESSED` selects a regular file's data source. When it is set, APFS and
HFS+ read the logical contents from `com.apple.decmpfs` and, for fork-based
compression types, `com.apple.ResourceFork`. When it is clear, the ordinary data
fork is authoritative. Leftover compression attributes do not activate decoding.

This distinction matters after a partial compression installation. For example,
the native compressor can write the attribute and resource fork but fail to
truncate the ordinary data. A later ordinary write can then change the data fork
without removing those attributes. Reading the stale compressed copy would
silently return the wrong file contents. A failure after truncation but before
activation can instead leave an empty ordinary file with retained storage.

## Reading and writing images

Both image readers honor the recorded compression flag. With the flag clear,
valid, malformed and unknown compression attributes remain opaque metadata;
they do not change the file's size or contents. The APFS reader also reads
extent-backed `decmpfs` attributes: compression that stores its payload inline
inside an attribute does not require that attribute to be embedded inside the
APFS B-tree record. It reads the fixed header and streams the stored payload.

For `apfswrite.Entry` and `hfsplus.Entry`, select `BSDFlags` explicitly to preserve
inactive storage beside ordinary data:

```go
flags := uint32(0)
entry.BSDFlags = &flags
```

Nil `BSDFlags` retains the existing inference of compression from the attribute.
An explicitly set compression flag still requires valid compression storage;
format, size and missing-storage checks remain enforced. Explicit flags do not
remove HFS catalog representability limits.

Metadata carriers retain the selected flags, raw attributes, resource fork and
ordinary payload independently. An edited ordinary payload is not replaced by
inactive compressed bytes during repacking. Decompression options apply to
active compression; they do not delete inactive attributes or an independent
resource fork. Native metadata projection likewise treats inactive storage as
ordinary attributes rather than suppressing it as a compressed payload.

## Qualification

The retained C oracle and both Clang AST targets are generated by
`scripts/capture-compression-state.go`. The corpus contains 160 native APFS/HFS+
cases covering five native compression requests, both storage choices and eight
states: active, ordinary full data, ordinary empty data, a subsequent ordinary
edit, malformed magic, truncated header, unknown type and absent resource fork.
Codec output comes from the retained native compression lifecycle corpus.

The committed native images, observations and source hashes live under
`testdata/appledouble/native/compression-state*`. Every comparison includes the
complete logical bytes, logical size, compression/hidden flags and raw attribute
and resource-fork bytes. A fresh capture never rewrites the baseline in check
mode.

```sh
go run scripts/verify-compression-state.go
go run scripts/capture-compression-state.go -check
```

The portable gate requires 480 image-reading, image-writing and carrier round-trip
cases, no skipped tests, and greater than 95% coverage of the new compression
storage implementation. The existing writer, flags and metadata transport gates
remain mandatory. CI runs the portable cases on Linux, Windows and both macOS
runners, then independently mounts Linux/Windows writer and carrier outputs on
both macOS runners. It retains full observations, image digests, Clang evidence
and attachment/detachment logs.

This corrects stored-state interpretation and preservation. Complete path-based
recompression still requires acquisition, eligibility, staging, volume context
and queue-admission behavior around the [installation APIs](compression-writer.md).
